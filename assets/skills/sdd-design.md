# sdd-design

Disenar la implementacion antes de dividir tareas.

## Pasos

1. Mapear componentes afectados.
2. Definir cambios de datos, interfaces o contratos.
3. Identificar dependencias y orden de implementacion.
4. Confirmar que los artefactos documentales se escriben mediante `docs_*` en el vault externo y no dentro del repo objetivo.
5. Si la peticion fue natural, resolver ruta y version internamente; una ambiguedad real admite una sola aclaracion y un conflicto nunca se sobrescribe.

## Salida

- Diseno tecnico.
- Archivos previstos.
- Impacto esperado.
- Proxima fase: `sdd-tasks`.
