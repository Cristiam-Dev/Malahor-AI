# sdd-archive

Cerrar el flujo SDD y guardar conocimiento relevante.

## Pasos

1. Resumir decision, implementacion y validacion.
2. Guardar en Mnemo decisiones, bugs, patrones o aprendizajes.
3. Actualizar mediante `docs_*` el cambio SDD y su estado humano cuando aplique.
4. Indicar estado final y siguientes pasos.
5. No crear archivos de cierre dentro del repo objetivo ni usar filesystem/Obsidian MCP como fallback.
6. No borrar documentacion permanentemente: moverla a archivo con la version vigente y reportar el path resultante.

## Salida

- Resumen final.
- Memorias guardadas.
- Estado de commit sugerido si aplica.
