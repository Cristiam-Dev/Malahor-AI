# git-pr-review

Preparar o revisar cambios antes de abrir un PR.

## Pasos

1. Revisar commits incluidos.
2. Revisar diff contra la rama base si esta disponible.
3. Identificar riesgos de comportamiento, seguridad y calidad.
4. Verificar que pruebas o build relevantes fueron ejecutados.
5. Proponer resumen y checklist de PR.

## Salida

- Resumen de cambios.
- Riesgos principales.
- Pruebas ejecutadas.
- Brechas pendientes.
- Texto sugerido para PR si el usuario lo pide.
